# Limitations

This is an honest list of what ORA does not do in this checkout. Each item is tied to the current implementation.

## File Edits Are Confined to the Configured Repository Root

`fs.write`, `fs.patch`, and repository reads are confined to the root derived from `--root`/`--cwd` ([`execution/patch.js`](../execution/patch.js), [`repo-intelligence/scanner.js`](../repo-intelligence/scanner.js), [`security/permissions.js`](../security/permissions.js)). ORA does not write outside that boundary through its file tools. There is **no OS-level sandbox**: `shell.exec` runs `/bin/bash -c` and can read or write anywhere the process user can, so the boundary is a tool-level policy, not a containment guarantee. Changing `--root` or `--cwd` changes the boundary.

## Model-Assisted Agent Planning Is Opt-In and Needs a Reachable Provider

The planner is deterministic and token-based by default ([`agents/planner.js`](../agents/planner.js)); it does not reason about code semantically. `ORA_USE_MODEL=1` only enables model-generated actions inside `agent.delegate` ([`agents/orchestrator.js`](../agents/orchestrator.js)). Those actions require a reachable provider; on any routing error, the agent emits `agent:model_fallback` and uses deterministic actions instead. The main task plan is never generated by a model in this implementation.

## FreeLLMAPI Key Is Absent, So the Chat Route Is Unverified

The default FreeLLMAPI provider is registered against `http://127.0.0.1:3001/v1`, but no key is available in this environment. `providers check` confirms that the gateway returns HTTP 401 on `/v1/models`. The `/chat/completions` route has therefore not been verified end to end. This is an external blocker, not a runtime defect. See [Configuration](CONFIGURATION.md#freellmapi-integration).

## No Automatic Internet Installation of Adapters

`adapters install` in the lifecycle API only registers an in-memory definition ([`adapters/lifecycle.js`](../adapters/lifecycle.js)). ORA never downloads, builds, or installs adapter software. Commands must already exist on `PATH`, and definitions persisted in `.ora/config.json` are re-registered when a runtime starts.

## Patches Support Unified Diffs Only

[`execution/patch.js`](../execution/patch.js) parses `--- a/`, `+++ b/`, and `@@ -old +new @@` hunks with exact context matching. There is no fuzzy matching, rename detection, binary patch support, or three-way merge. Context drift produces `patch context mismatch`; use `fs.write` or regenerate the diff in that case. Multi-file patches are not atomic: files processed before an error remain modified.

## Conflicts Are Marked Review-Required, Not Auto-Merged

When two parallel agents touch the same path with different resulting hashes, `runParallel` records a conflict with `resolution: 'review-required'` and marks the agent result as `conflict` ([`agents/orchestrator.js`](../agents/orchestrator.js)). ORA does not attempt a merge. Conflicts are attached to the task via `tasks.addConflict` and surfaced in `task show`/the task result.

## The Web Dashboard Is Read-Only

[`ui/server.js`](../ui/server.js) serves one HTML page and GET endpoints only. It cannot start tasks, approve requests, edit files, or change configuration. It also holds its own runtime instance and reads state at startup, so it does not automatically reflect task data written by later CLI invocations.

## Approval Decisions Do Not Survive the Process

The approval gate stores pending and resolved requests in in-memory maps ([`security/permissions.js`](../security/permissions.js)). Nothing is persisted to `<stateDir>`. A CLI invocation creates a new gate, so decisions made in one process are unknown to the next. A non-interactive CLI invocation denies approval-requiring work rather than queuing it for later.

## Additional Current Gaps

- `task resume` re-plans and reruns the full step sequence; it does not resume from the last step ([`core/runtime.js`](../core/runtime.js)).
- Checkpoints can be listed through `status`/`task show` and restored through the library API, but there is no CLI restore command ([`core/state.js`](../core/state.js)).
- `npm test`, `npm run check`, and `npm run smoke` are the implemented verification paths; external model and adapter routes still require credentials or installed commands ([`package.json`](../package.json)).
- Generated test fixtures are written under `.ora-state-tests`; `npm run check` skips that directory.
- The repair pass runs at most once per task and is skipped for `agent.delegate` steps; plan length is capped at `runtime.maxSteps` (30) and delegation actions at `agents.maxActionsPerAgent` (12).
- The shell executor assumes `/bin/bash` is available ([`execution/shell.js`](../execution/shell.js)).
